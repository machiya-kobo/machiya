Machiya

Your own search for everything you read, write and build, on your own server.

  • Hister keeps your own index of every page you visit and save, so you can find any of them again.
  • Your Obsidian vault is searched alongside it, read in Kura, published in Niwa's garden and planned on Konbini's board.
  • The web comes from SearXNG and the small web, in the same search, without sharing your history.
  • Your code repositories on Forgejo and GitHub: READMEs, docs, issues, pull requests and releases.

The Rooms

Four services, each in its own repository with its own image. Links between them are optional: leave one out and the others carry on.

Kura

the storehouse

Every note in the vault, with working links.

  • A reader: folders, tags, backlinks and a preview pane
  • Full-text search
  • A JSON API for notes
  • Pushes every note into Hister, so your notes and your pages are searched together

machiya-kobo/kura

Niwa

the garden

The published garden, grown from the vault.

  • A note is in the garden when its frontmatter says publish: true, set from Niwa's own Publish button
  • Growth stages, backlinks, topic maps and a stream of what changed
  • A check before publishing for addresses, keys and tokens
  • Served on the web, and over Gemini and Gopher

machiya-kobo/niwa

Konbini

the shop

The project board, built from the vault's project notes.

  • Backlog, ready, WIP, blocked, done; lanes, priorities, next actions and blockers
  • Review, plan, calendar and roundups for the day, week, month and year
  • The notes are the source of truth: a board edit is a frontmatter line, committed to git
  • pm, a one-file command line for the board

machiya-kobo/konbini

Shiori

the bookmark

The search front door: your pages, your notes and the web, in one search.

  • Apps for iPhone, iPad and Mac, a Safari extension, a Linux app and a web app
  • Searches Hister, Kura and SearXNG at once
  • A note opens in Kura to read, or in Obsidian to edit

machiya-kobo/shiori

The Engines

Machiya builds on two open-source search services, run as their upstream images with reference configuration in the machiya repository:

  • Hister indexes every page you visit or save, and, through Kura, your notes.
  • SearXNG searches the web, optionally through a SOCKS proxy. It never queries Hister: SearXNG can be shared, and your history stays yours.

Beside the Rooms

The machiya repository also holds the stack's smaller pieces: a landing and status page, an MCP server and a Claude Code plugin for the rooms, importers that bring feeds and code repositories into Hister, and vaultkit, the shared vault core every room vendors at a tag.

How It Fits Together

  • The vault is the source of truth. Each room clones it and keeps the clone current; run together, they can share one mirror. Anything a room stores besides that can be rebuilt from git.
  • Kura only reads. Niwa writes only the garden fields (publish, growth, confidence, garden_pin). Konbini writes only board fields and new stub notes, and never edits a note's body.
  • Kura pushes notes into Hister, labelled vault, so a search for pages finds notes too.
  • Shiori asks the others: Hister for pages, Kura for notes, SearXNG for the web. When one is missing, that part of the search is simply left out.

Principles

  • Each Runs on Its Own

    Own repository, own image, own copy of the vault. Links to the other rooms are optional URLs; when one is unset, the feature that needs it turns off and nothing else breaks.

  • Metadata in Frontmatter

    A board column, a next action, a garden stage, a due date: anything a room knows about a note is a field in that note's frontmatter, not a separate database.

  • Owner-Only

    Pages and APIs answer only the people you name. Agents and other people get exactly the grants you give them, and a header a caller writes is never a permission.

  • Private by Default

    Out of the box every room binds to 127.0.0.1, and behind the tailnet gate an empty allow-list lets nobody in. Your history stays in Hister: the web search never queries it, and Shiori loads image thumbnails through SearXNG, never from an engine directly.

  • Tailnet-Friendly

    Each room can sit behind its own Tailscale Service and trust the tailnet's login, or behind your own proxy or sign-in.

  • Runs Where You Do

    Every image is native on amd64 and arm64. Run the stack with Docker or Podman, or Kura, Niwa and Konbini natively on Linux, FreeBSD, NetBSD and OpenBSD.

The full list, and what each room must not do: docs/principles.md.

Get Started

The machiya README has the steps, tested on a fresh clone. They aren't copied here so they can't drift.

  • Try it with the sample vault: the whole stack on one machine with a small invented vault, in about ten minutes.
  • Quickstart: the whole stack on your own vault.
  • Just one room: Kura, Niwa, Konbini or Shiori, each with its own quickstart.
  • Native installs on the BSDs, as rc.d services.

Machiya is pre-1.0, so expect change. The APIs between the rooms are written down in docs/contracts.
